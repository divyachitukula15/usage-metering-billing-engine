10. Added webhook signature verification and duplicate-event handling.
11. Added checkout-completion synchronization between the local subscription and tenant plan.

14. Removed automatic `Base.metadata.create_all()` from application startup so schema changes are managed by migrations.
15. Added a database-backed background-job record and usage-cost processing triggered through FastAPI `BackgroundTasks`.

17. Added tests for background-job completion, retry/failure behavior, missing/invalid API keys, and quota response headers.

## Debugging examples

- Alembic initially detected index differences between the existing database and SQLAlchemy metadata. The model declarations were aligned with the existing indexes, and `alembic check` then reported no new upgrade operations.
- The existing database was stamped at the baseline migration rather than applying an autogenerated migration that would have dropped existing indexes.
- The new `background_jobs` table was added with a separate Alembic migration.
- Usage endpoint tests exposed an empty JSON response when returning a SQLAlchemy object directly. The endpoint response was changed to an explicit dictionary, and the usage tests passed.
- Background-job processing was updated to accept a session factory so tests can use their configured SQLite database session rather than opening a separate application database connection.

## Known limitations

- Background tasks run in the API process. There is no separate persistent worker or automatic recovery of pending jobs after a process crash/restart.
- Retry attempts are performed within one invocation; permanent failures are logged but no external alert is sent.
- API-key authentication currently protects usage endpoints. The remaining routes need a full authorization review.
- API-key rotation/revocation and rate limiting are not implemented.
- Usage counts are supplied by the caller; no LLM provider integration verifies them.
- Cost output is stored in the background-job payload, not a dedicated invoice/ledger table.
- Production deployment, monitoring, and operational hardening remain future work.
